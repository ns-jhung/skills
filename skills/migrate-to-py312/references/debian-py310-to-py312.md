# Debian-only: Python 3.10 → 3.12

Reference PR: https://github.com/netSkope/ep-sample-build-app/pull/35

This is the **simplest** migration — Debian-only components don't have Dockerfiles to update, just build configs and dependencies.

## Files to change

- `Makefile`
- `requirements.txt` (regenerated via `uv pip compile`)
- `app-env-py312.yaml` (generated by `conda-env-gen`; delete old `app-env-py310.yaml`)
- `tox.ini`
- `pyproject.toml` (create if missing — required for PEP 517 wheel build under py312)

**Not touched:** `Dockerfile-2004`, `Dockerfile-2004-fips` (Debian components don't have these)

## Step 1 — Makefile

Two changes:
1. Bump `PYTHON_VERSION` to `py312`.
2. Add `export PIP_INDEX_URL=...org-external-pypi/simple` (and `SETUPTOOLS_USE_DISTUTILS=local`) so the PEP 517 isolated build env can resolve `setuptools>=70.0.0`. Without this, the Drone wheel build fails with:

   ```
   ERROR: Could not find a version that satisfies the requirement setuptools>=70.0.0
          (from versions: 44.1.1, 57.4.0, 59.2.0)
   Looking in indexes: https://artifactory-rd.netskope.io/artifactory/api/pypi/netskope-py38/simple
   ```

   The Drone builder image's `/etc/pip.conf` points at the legacy `netskope-py38` index. Local `pip-unbounded.conf` is copied into the conda builder env, but `python -m build -w` spawns a PEP 517 isolated venv at `/tmp/build-env-XXX/` that does **not** inherit it — pip falls through to `/etc/pip.conf`. Only a process-level env var (`PIP_INDEX_URL`) overrides the file-level config for that ephemeral venv.

```diff
-PYTHON_VERSION           ?= py310
+PYTHON_VERSION           ?= py312

 VIRTUALENV_PYPI_TYPE=unbounded

+export PIP_INDEX_URL=https://artifactory-rd.netskope.io/artifactory/api/pypi/org-external-pypi/simple
+export SETUPTOOLS_USE_DISTUTILS=local
+
 ## Do not modify the following vars or include logic ##
```

Reference: `dp-py-apps/ipsconfigmanager/Makefile` (commit `52fcd3fc25b`, ENG-986779) is the canonical working pattern.

## Step 2 — Print this `uv pip compile` command for the user

```bash
docker run \
  --mount type=bind,source="$(pwd)",target=/ep-tools/uv \
  artifactory-rd.netskope.io/org-tool-release-docker/ns-builder/develop-uv-python3.12-ubuntu2004-current:26.84.3019 \
  uv pip compile \
  --python-version=3.12 \
  --emit-index-url \
  --generate-hashes \
  -o requirements.txt \
  requirements.in
```

Substitute `$(pwd)` with the absolute path to the component directory.

Substitute `/path/to/repo` and `<component-name>`. After the user runs it, **delete `app-env-py310.yaml`**.

## Step 4 — tox.ini

Three changes:
- `envlist`: `py310` → `py312`
- `find-links` path: `{env:NS_BUILD_DIR}/components/<component>/dist` → `{toxinidir}/dist`
- `conda_env`: `app-env-py310.yaml` → `app-env-py312.yaml`

```diff
 ### tox configuration ###
 [tox]
-envlist = py310
+envlist = py312
 requires = tox-conda

 [testenv]
@@
 install_command =
     pip install \
-    --find-links file://{env:NS_BUILD_DIR}/components/edr-client/dist \
+    --find-links file://{toxinidir}/dist \
     {opts} {packages}

-conda_env = app-env-py310.yaml
+conda_env = app-env-py312.yaml
 conda_channels=
     conda-forge
```

(The `edr-client` path is from the reference PR; replace with the actual component name.)

## Step 5 — pyproject.toml (create if missing)

Components with only `setup.py` and no `pyproject.toml` will fail the Drone wheel build under py312 with:

```
ERROR Backend 'setuptools.build_meta:__legacy__' is not available.
Failed to build wheel for /drone/src/dp-py-apps/<component>
```

Root cause: `python -m build` in the py312 conda env (newer `build` + `setuptools` 70+) no longer falls back to the legacy backend alias when no `pyproject.toml` is present.

Fix: create a 3-line `pyproject.toml` next to `setup.py`:

```toml
[build-system]
requires = ["setuptools>=70.0.0", "wheel"]
build-backend = "setuptools.build_meta"
```

Reference: `dp-py-apps/ipsconfigmanager/pyproject.toml` is identical and was added during its py312 migration.

If `pyproject.toml` already exists, leave it alone — only create when missing.

## Critical notes

✅ DO:
- Update Makefile `PYTHON_VERSION` to `py312`
- Run `uv pip compile` to regenerate `requirements.txt`
- Use `conda-env-gen` for the YAML — never hand-edit
- Delete `app-env-py310.yaml` after generating new YAML
- Create `pyproject.toml` if it doesn't exist (otherwise wheel build will fail in Drone)

❌ DON'T:
- Manually edit `app-env-py312.yaml`
- Keep `app-env-py310.yaml` around after migration
- Skip regenerating `requirements.txt`
