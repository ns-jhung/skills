# Stork-Debian: Python 3.10 → 3.12

Reference PR: https://github.com/netSkope/ep-sample-build-app/pull/36

This is the **incremental** Stork migration. The build system (`conda-build.mk`, `tox-conda`) is already in place from the prior py310 migration; you only need to bump version numbers and base images.

## Files to change

- `Makefile`
- `requirements.txt` (regenerated via `uv pip compile`)
- `app-env-py312.yaml` (generated by `conda-env-gen`; delete old `app-env-py310.yaml`)
- `tox.ini`
- `Dockerfile-2004`
- `Dockerfile-2004-fips`
- `pyproject.toml` (create if missing — required for PEP 517 wheel build under py312)

## Step 1 — Makefile

```diff
-PYTHON_VERSION          ?= py310
+PYTHON_VERSION          ?= py312
```

## Step 2 — Print this `uv pip compile` command for the user

The user runs this from the component directory (the one with `requirements.in`):

```bash
docker run \
  --mount type=bind,source="$(pwd)",target=/ep-tools/uv \
  artifactory-rd.netskope.io/org-tool-release-docker/ns-builder/develop-uv-python3.12-ubuntu2004-current:26.84.3019 \
  uv pip compile \
  --python-version=3.12 \
  --emit-index-url \
  --generate-hashes \
  -o requirements.txt \
  requirements.in
```

Substitute `$(pwd)` with the absolute path to the component directory if you want the user's copy-paste to be self-contained. The image tag (`26.84.3019`) can be bumped to whatever is current at https://tool-ep-pokeball.netskope.io/#!/taglist/ns-builder/develop-uv-python3.12-ubuntu2004-current — but this tag is recent and usually fine.

## Step 3 — Print this `conda-env-gen` command for the user

```bash
docker run \
  --rm \
  --mount type=bind,source="/path/to/repo",target=/cenv/repo \
  artifactory-rd.netskope.io/org-tool-release-docker/ns-utilities/conda-env-gen-ubuntu2404-current:26.85.3004 \
  -p 3.12 \
  -r repo/components/<component-name>/requirements.txt
```

Substitute:
- `/path/to/repo` → the absolute path of the repo root
- `<component-name>` → the actual component directory name

This produces `app-env-py312.yaml`. After running it, the user should **delete `app-env-py310.yaml`**.

> Important: do NOT manually edit or hand-copy the generated YAML. It contains conda channel ordering and package hashes that only the tool gets right.

## Step 4 — tox.ini

Three changes:
- `envlist`: `py310` → `py312`
- `find-links` path: `{env:NS_BUILD_DIR}/components/<component_name>/dist` → `{toxinidir}/dist`
- `conda_env`: `app-env-py310.yaml` → `app-env-py312.yaml`

```diff
 ### tox configuration ###
 [tox]
-envlist = py310
+envlist = py312
 requires = tox-conda

 [testenv]
@@
 install_command =
     pip install \
-    --find-links file://{env:NS_BUILD_DIR}/components/clientstatus/dist \
+    --find-links file://{toxinidir}/dist \
     {opts} {packages}

-conda_env = app-env-py310.yaml
+conda_env = app-env-py312.yaml
 conda_channels=
     conda-forge
```

(The `clientstatus` path is from the reference PR; replace with the actual component name in the user's tox.ini.)

## Step 7 — pyproject.toml (create if missing)

Components with only `setup.py` and no `pyproject.toml` will fail the Drone wheel build under py312 with:

```
ERROR Backend 'setuptools.build_meta:__legacy__' is not available.
Failed to build wheel for /drone/src/dp-py-apps/<component>
```

Root cause: `python -m build` in the py312 conda env (newer `build` + `setuptools` 70+) no longer falls back to the legacy backend alias when no `pyproject.toml` is present.

Fix: create a 3-line `pyproject.toml` next to `setup.py`:

```toml
[build-system]
requires = ["setuptools>=70.0.0", "wheel"]
build-backend = "setuptools.build_meta"
```

Reference: `dp-py-apps/ipsconfigmanager/pyproject.toml` is identical and was added during its py312 migration.

If `pyproject.toml` already exists, leave it alone — only create when missing.

## Critical notes

✅ DO:
- Update **both** Dockerfiles
- Run `uv pip compile` to regenerate `requirements.txt`
- Use a real version tag for the base image
- Delete `app-env-py310.yaml` after generating `app-env-py312.yaml`
- Build and test locally
- Create `pyproject.toml` if it doesn't exist (otherwise wheel build will fail in Drone)

❌ DON'T:
- Use `latest` tag (we don't publish it)
- Manually edit `app-env-py312.yaml`
- Mix py310 and py312 base images in the same build
- Keep `app-env-py310.yaml` around after migration
- Forget the FIPS Dockerfile
