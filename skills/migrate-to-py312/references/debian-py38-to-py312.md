# Debian-only: Python 3.8 → 3.12

Reference PR: https://github.com/netSkope/ep-sample-build-app/pull/37

This is a **major** Debian migration — the build system switches from `pythonpkg-py3.mk` to `conda-build.mk`, and dependencies often need significant updates (py38 → py312 spans years of package evolution).

## Files to change

- `Makefile`
- `requirements.txt` (regenerated via `uv pip compile`)
- `app-env-py312.yaml` (generated by `conda-env-gen`; delete old `app-env-py38.yaml`)
- `tox.ini`
- `pyproject.toml` (create if missing — required for PEP 517 wheel build under py312)

**Not touched:** Dockerfiles (Debian components don't have these)

## Step 1 — Makefile

Five changes:
- Add `PYTHON_VERSION ?= py312`
- Add `COMPONENT_DIR` referencing the component path
- Add `APP_ENV_YML` using the dynamic Python version
- Switch `PYTHONPKG_MK_FILE` from `pythonpkg-py3.mk` to `conda-build.mk`
- Add `export PIP_INDEX_URL=...org-external-pypi/simple` (and `SETUPTOOLS_USE_DISTUTILS=local`) so the PEP 517 isolated build env can resolve `setuptools>=70.0.0`. See "PIP_INDEX_URL note" below.

```diff
 WHAT                     = PDD Upload Service
+PYTHON_VERSION           ?= py312
 SERVICE_NAME             = pdd-upload-service
 DEB_PKG_NAME             = pdd-upload-service
 DEVELOP_EDITABLE         = yes
@@
 VENV_PIP                 = 24.1.2
 VENV_SETUPTOOLS          = 72.1.0

+export PIP_INDEX_URL=https://artifactory-rd.netskope.io/artifactory/api/pypi/org-external-pypi/simple
+export SETUPTOOLS_USE_DISTUTILS=local
+
 ## Do not modify the following vars or include logic ##
+COMPONENT_DIR     = $(NS_BUILD_DIR)/components/debian-py38
+APP_ENV_YML       = $(COMPONENT_DIR)/app-env-$(PYTHON_VERSION).yaml
 MK_DIR            = $(NS_BUILD_DIR)/compile
-PYTHONPKG_MK_FILE = $(MK_DIR)/pythonpkg-py3.mk
+PYTHONPKG_MK_FILE = $(MK_DIR)/conda-build.mk
 HAVE_MK_PYTHONPKG = $(shell test -r $(PYTHONPKG_MK_FILE) && echo yes)
```

Substitute `pdd-upload-service` and `debian-py38` with the user's actual component values.

**PIP_INDEX_URL note.** Without the `export PIP_INDEX_URL=...` line, the Drone wheel build fails:

```
ERROR: Could not find a version that satisfies the requirement setuptools>=70.0.0
       (from versions: 44.1.1, 57.4.0, 59.2.0)
Looking in indexes: https://artifactory-rd.netskope.io/artifactory/api/pypi/netskope-py38/simple
```

The Drone builder image's `/etc/pip.conf` points at the legacy `netskope-py38` index. Local `pip-unbounded.conf` is copied into the conda builder env, but `python -m build -w` spawns a PEP 517 isolated venv at `/tmp/build-env-XXX/` that does **not** inherit it — pip falls through to `/etc/pip.conf`. Only a process-level env var (`PIP_INDEX_URL`) overrides the file-level config for that ephemeral venv. Reference: `dp-py-apps/ipsconfigmanager/Makefile` (commit `52fcd3fc25b`, ENG-986779).

## Step 5 — pyproject.toml (create if missing)

Components with only `setup.py` and no `pyproject.toml` will fail the Drone wheel build under py312 with:

```
ERROR Backend 'setuptools.build_meta:__legacy__' is not available.
Failed to build wheel for /drone/src/dp-py-apps/<component>
```

Root cause: `python -m build` in the py312 conda env (newer `build` + `setuptools` 70+) no longer falls back to the legacy backend alias when no `pyproject.toml` is present.

Fix: create a 3-line `pyproject.toml` next to `setup.py`:

```toml
[build-system]
requires = ["setuptools>=70.0.0", "wheel"]
build-backend = "setuptools.build_meta"
```

Reference: `dp-py-apps/ipsconfigmanager/pyproject.toml` is identical and was added during its py312 migration.

If `pyproject.toml` already exists, leave it alone — only create when missing.

## Critical notes

✅ DO:
- Carefully review all dependencies for py312 compatibility
- Test thoroughly before committing
- Be aggressive cleaning up legacy py38 packages from `requirements.in`
- Delete `app-env-py38.yaml` after generating new YAML
- Create `pyproject.toml` if it doesn't exist (otherwise wheel build will fail in Drone)

❌ DON'T:
- Assume py38 packages work on py312
- Skip dependency testing
- Mix Python versions
- Keep `app-env-py38.yaml` around after migration
